# SDD decisions

| Date | Decision | Options considered | Why |
|------|----------|--------------------|-----|
| 2026-09-24 | Web framework: Flask + Jinja2 | FastAPI, Flask | The owner wants to learn Flask. |
| 2026-09-24 | Database: PostgreSQL on Supabase | Local Postgres container, Supabase | Managed database; removes a container from the 2 GB server. |
| 2026-09-24 | Dependency management: Poetry | pip + requirements.txt, Poetry, uv | Lockfile-based reproducible installs; owner's choice. |
| 2026-09-24 | LLM provider: Gemini (`google-genai`), default model `gemini-3.1-flash-lite`, switchable via `LLM_PROVIDER`/`LLM_MODEL` | OpenAI SDK, Gemini 2.5 Flash-Lite, Gemini 3.1 Flash-Lite, Gemini 3.5 Flash-Lite | Cheapest Flash model open to new projects ($0.25/$1.50 per 1M tokens); 2.5 models are restricted to prior users. 3.1 shuts down 2027-05-07, so the move to 3.5 Flash-Lite is one `.env` line. |
| 2026-09-24 | Base image stays `python:3.12-slim` (Debian 13.7) despite HIGH CVEs flagged by scanners | Keep slim + rebuild with `--pull` regularly; Alpine; distroless; Chainguard | Trivy: every HIGH is in OS packages (util-linux/mount, ncurses, systemd libs, acl, perl-base) with no fixed version released, so no image or `apt upgrade` removes them today. They need privileged mount/nsenter or local terminal/tar input the app never exposes, and the app runs as non-root. Alpine risks musl wheel issues (pypdfium2, psycopg), distroless ships a different Python, Chainguard pins need a paid tier. Python deps: 0 CVEs. Re-scan with Trivy at step 13 and before deploy. |
| 2026-09-24 | Extraction schema covers 10 document types, not only invoices | Invoice-only schema; one model per type as a Union; one root model with a nullable section per type | Owner wants general IDP. Root model + nullable sections is the shape both Gemini and OpenAI structured outputs support reliably; the validator keeps only the section matching `document_type`. Bank statements store only the last 4 account digits (privacy); transaction lists and ID documents are out of MVP scope. |
| 2026-09-24 | Line length 120 (was 100) for ruff lint and formatter | 100 with inline comments banned; 120 | Owner wants short comments to the right of code. The formatter counts trailing comments in the width, so at 100 it wrapped code in parentheses to make room. |
| 2026-09-24 | Ephemeral mode + CSV export, adapted from a FastAPI-based spec to Flask | Store ephemeral results in Postgres with a flag; keep them only in the browser; Celery Redis result backend with TTL | The spec named FastAPI, but the stack is Flask (principle 18): `StreamingResponse` becomes a Flask streamed `Response`. Every task returns its data to the Redis result backend (both modes), so status and results come from Celery for everyone and the `documents` table stores only persisted results, without a status column. Task ids are random UUIDs; there is no auth in the MVP scope. |
| 2026-09-24 | Tables created with `Base.metadata.create_all` + RLS enabled (`python -m app.db`), no Alembic yet | Alembic migrations; raw SQL; `create_all` | One table and no production data yet: `create_all` is idempotent and simplest to learn. Adopt Alembic before the first schema change once real data exists. RLS on with no policies closes Supabase's public REST API; the app connects as table owner. |
| 2026-09-24 | Text sent to the LLM capped at 60,000 characters; scanned PDFs rejected with a clear error | No cap; cap by pages; OCR (Tesseract) | ~15k tokens cover invoices, contracts and most reports while bounding cost per document, and reading stops early so long PDFs are not fully parsed. OCR would add a heavy binary and RAM to a 2 GB server; it stays out of the MVP and scans fail with `NoTextLayerError` instead of sending empty text to the LLM. |
| 2026-09-24 | Validate every LLM output with our own Pydantic call, not the SDK's parsed result; split errors into transient and permanent | Trust structured output; use `response.parsed`; single error type | Structured output shapes the answer but does not guarantee it, and `google-genai`'s `response.parsed` returns None silently on a mismatch. One `parse_response()` for all providers makes rejection explicit and keeps document content out of error messages. `LLMTransientError` (429, 408, 5xx, network) lets the Celery task retry only what can succeed later. |
| 2026-09-24 | Task retries: only transient LLM and database errors, exponential backoff (10 s → 300 s cap), max 3; results in Redis db 1 with a 1 h TTL | Retry everything; no retries; `autoretry_for` | Invalid LLM output or a scanned PDF will fail the same way again, so retrying them only costs money. The PDF must survive a pending retry, so it is deleted in `finally` unless a retry was scheduled. Results live apart from the queue (db 1) and expire, so ephemeral data never outlives `RESULT_TTL_SECONDS`. A worker killed mid-task (OOM) leaves its PDF behind: a periodic sweep of old files is a follow-up. |
| 2026-09-24 | CSV layout: unified columns derived from the schema (64, fixed) and individual CSV with one row per line item | Columns from the data present in each batch; JSON-in-a-cell; one CSV per type | Fixed columns let batches be stacked and compared in a spreadsheet; line items as rows is the usual accounting export shape. Only text cells are escaped against formula injection so amounts stay numeric. |
| 2026-09-24 | Task results are served only to the browser that uploaded them: owner token in a signed session cookie + owner sets in Redis | Unguessable task id only; task ids in the cookie itself; user accounts | Without auth (out of MVP scope) a task id worked like a secret link that can leak through logs, screenshots or history. A random owner token in a signed, HttpOnly, SameSite=Lax cookie plus a Redis set per owner (TTL = results TTL) closes that, has no cookie size limit (a cookie fits only ~100 ids) and unknown or foreign ids both return 404. CSV endpoints need no ownership: they only transform JSON the browser sends. |
| 2026-09-24 | Export formats: CSV, XLSX and JSON from one typed table | CSV only; openpyxl or pandas for XLSX; ODS | These three cover spreadsheets (XLSX), any tool (CSV) and other systems (JSON). XlsxWriter is write-only, fast and light (no pandas on a 2 GB server) and `write_string` keeps text from ever becoming a formula. Building a typed table once keeps all formats consistent; XLSX also removes CSV's leading-zero problem. |
| 2026-09-24 | Browser UI in plain HTML/CSS/JS with Chart.js from a pinned, SRI-checked CDN URL and a strict CSP | React/Vue SPA; vendoring Chart.js; no charts | One page does not justify a build pipeline; plain JS keeps the image small. SRI makes the CDN file tamper-evident and the CSP forbids inline scripts, so XSS needs both an injection point (none: textContent only) and a CSP bypass. |
| 2026-09-24 | No pip in the runtime image; threaded gunicorn (2 workers × 4 threads) | Keep pip; sync workers; more processes | pip is never used at runtime and its vendored libraries carried the only fixable CVEs in the image. Threads let polling proceed while uploads stream, without the RAM cost of more processes. |
| 2026-09-25 | Accounts: email + password (PBKDF2 600k) and Google OAuth (code + PKCE, userinfo); sessions in Flask's signed cookie; new accounts active by default with optional manual approval | JWT in localStorage; Auth.js in Next.js; scrypt/argon2 | One backend owns users, quotas and payments. HttpOnly cookies keep tokens away from JavaScript. PBKDF2 needs no extra memory per login (scrypt ~32 MB) on a 384 MB container. The owner asked both for automatic acceptance and manual approval: default active, `REQUIRE_MANUAL_APPROVAL=true` for pending-first. |
| 2026-09-25 | Plans: Free (2 PDFs / 24 h) + Starter $1.99, Pro $4.99, Business $9.99, Ultra $19.99 as 30-day passes; saving to history is a paid privilege | Monthly subscriptions; credits; free with DB | Passes avoid subscription webhooks and failed-renewal states; one-time PayPal Orders are simpler and verifiable in one request. Prices cover the worst-case Gemini cost. Storage costs money, so it is a paid privilege. |
| 2026-09-25 | Frontend: Next.js 16 static export served by Caddy (compiled with patched Go) instead of a Node.js server | Next.js server (SSR); nginx + certbot | A static site needs no Node.js process (~150-250 MB saved on 2 GB), and Caddy gives automatic HTTPS. The official Caddy binary lagged Go security fixes (17 fixable CVEs); building it with Go 1.26.8 and patched modules gets 0. Trade-off: CSP must allow inline scripts for Next.js's static bootstrap. |
| 2026-09-25 | Edge server: Nginx 1.30 (stable) + a certbot service instead of Caddy; supersedes the Caddy decision above | Keep Caddy; Nginx + certbot; Traefik | The owner prefers Nginx (industry standard, worth learning). Nginx has no automatic HTTPS, so certbot (production-only Compose profile) obtains and renews Let's Encrypt certificates over the HTTP-01 webroot, and Nginx installs them and reloads within a minute. A 7-day self-signed placeholder lets Nginx start before the first certificate exists. Uploads keep streaming (`proxy_request_buffering off`), and "web" is resolved per request so a restarted API never gives 502s. No custom compile needed: the official Alpine image is patched on every build. Cost: +128 MB limit for certbot in production. |
| 2026-09-25 | Alembic migrations; the step-6 `documents` table adopted as revision 0001; the web container migrates on start | Manual SQL; `create_all` | Real users and payments now live in the database, so schema changes must be versioned and repeatable. Migrating on start keeps deploys to one command. |
| 2026-09-25 | Orphaned uploads removed by a Celery beat task every 30 min (files older than `ORPHAN_MAX_AGE_HOURS`) | Cron on the host; nothing | Covers workers killed mid-task. Embedded beat is fine with a single worker. |
| 2026-09-25 | Email through any SMTP provider (stdlib `smtplib`), sent on a background thread; without `SMTP_HOST` emails go to the logs | A provider SDK (Resend, SES); a Celery mail queue | No new dependency and no lock-in. The single Celery worker processes PDFs one at a time, so a mail queue there would wait minutes; a thread sends at once and hides account-existence timing. |
| 2026-09-25 | Verification and reset links are signed with `itsdangerous` (no table); reset tokens embed a password-hash fingerprint; tokens travel in the URL fragment | Random tokens stored in the database | Stateless and single-use at the same time (the fingerprint changes with the password). The fragment never reaches Nginx's access log. The same fingerprint in the session cookie signs out other sessions on a password change. |
| 2026-09-25 | Monthly PayPal Subscriptions next to the one-time passes; PayPal billing plans created on first use per (env, plan, price); plan runs to next billing + 3 days of grace | Only passes; billing plans created by hand in PayPal's dashboard | The owner asked for automatic renewal. Lazy creation means a price change in `app/plans.py` needs no manual PayPal step. The grace covers late charges without giving free months. |
| 2026-09-25 | PayPal webhooks verified with PayPal's verify-webhook-signature API using the raw body, applied once (`webhook_events` in the same transaction), plus a reconciliation task every 6 hours | Local certificate verification; trusting webhooks alone | The API call avoids certificate handling code; forwarding the raw bytes avoids false failures from re-serialization. Webhooks can be lost, so the periodic check keeps plans correct anyway. |
| 2026-09-25 | Charge per PDF page (plan allowances per 24 h / 30 days) plus pay-as-you-go page packs that never expire; packs replace the one-time 30-day passes | Per document; passes | A 1-page receipt and a 60-page report cost very different amounts to process; per-page pricing is fairer and allows larger PDFs. Pages are counted from the PDF page tree before processing and given back when a document fails. |
| 2026-09-25 | Frontend: light theme by default with a dark-mode button; English/Spanish i18n with typed catalogs, browser-language detection and a saved choice | next-intl; system color scheme | A static export has no server to negotiate the language, so a tiny head script picks theme and language before the first paint. Typed catalogs (es.ts must match en.ts) make a missing translation a build error. |
| 2026-09-25 | Upload hardening: inflate every compressed stream in 1 MB steps before any PDF parser and reject bombs; 450 MB data-memory ceiling per worker child; 300 s / 330 s task time limits | Trusting pdfminer; a separate sandbox process | A real 800 MB decompression bomb made the kernel kill the worker. The raw-byte check stops it at upload with a clear message; the ceiling and time limits turn anything that slips through into a clean task failure. |
| 2026-09-25 | Password policy after NIST SP 800-63B: 10-128 characters, no composition rules, refuse common passwords, sequences and passwords based on the email or name | Composition rules; a breached-password API | Composition rules make passwords predictable; length plus a blocklist is the standard's recommendation, with no external call on sign-up. |
| 2026-09-25 | Account deletion anonymizes the user row (status "deleted") and erases documents and usage; payments stay linked to the anonymized row; live subscriptions are cancelled first | Hard delete with cascade | Tax law requires keeping payment records; nothing personal remains in the kept row. Self-service in the account, an emailed confirmation link, or a request by email handled within 48 hours. |
